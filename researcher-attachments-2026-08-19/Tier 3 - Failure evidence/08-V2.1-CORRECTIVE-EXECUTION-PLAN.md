# 3. What went wrong in `47b3ac32`

The correction must explicitly guard against each failure class below.

## F1 — hard-coded benchmark outcomes

Examples in the failed attempt included fixed recall, precision, quality, wall-time, ASR accuracy, and product-rubric values written directly into evaluator code.

**Rule:** evaluator code may contain thresholds and rubric definitions, but **must not contain the measured result it is supposed to discover**.

Every published metric must be computed from raw per-case artifacts or recorded as `UNMEASURED`.

## F2 — simulations presented under real component names

Examples included:

- “GLiNER2” implemented as regex proper-noun extraction;
- “mDeBERTa” implemented as token overlap/negation heuristics;
- “HHEM” implemented as token-overlap scoring;
- “LangExtract provider” implemented as a period-splitting simulation.

**Rule:** a benchmark lane named after a real package/model must prove that package/model actually loaded and executed.

If a simulation is useful for adapter development, name it explicitly `SIMULATION` or `FAKE_FOR_TESTS`; it can never select, reject, promote, or score the real component.

## F3 — mocked subprocess tests treated as real semantic smoke tests

Mocked unit tests are valid T0 tests. They are **not** evidence that Claude/Codex/Antigravity actually executed.

**Rule:** HG01 requires at least one real local subprocess invocation receipt before any semantic lane may be benchmarked or promoted.

## F4 — P20 reported four-source PASS without running P20

The previous evaluator read existing reduce artifacts and assigned PASS/boolean checks rather than executing the selected lifecycle.

**Rule:** P20 must create a new corrective-run directory, execute every required Map/Reduce stage for all four sources through the selected semantic route, and preserve per-invocation receipts.

## F5 — P21 reported fresh E2E PASS without fresh audio-to-knowledge execution

The previous evaluator wrote fixed word counts and PASS strings.

**Rule:** P21 must start from fresh/reacquired audio (or a freshly hashed local audio artifact produced for this run), execute selected ASR, TTK custody, semantic Map, Reduce, verification routing, compile, and complete validation. Required: one English and one German source.

## F6 — clean-room resume was only mocked

The unit test is useful, but it is not the required T5 real execution proof.

**Rule:** P22/T5 must rerun a real semantic run from unchanged state and prove zero duplicate semantic invocations, then invalidate one unit and prove only that unit plus necessary downstream dependents rerun.

## F7 — generated receipts were mistaken for observed receipts

A receipt generated from a declaration table is not an execution receipt.

**Rule:** execution receipts must be written **after observing a real command/model invocation**, and must contain command/config identity, input hash, output hash where applicable, start/end/exit status, and validation result.

## F8 — final PASS could be written without raw evidence closure

**Rule:** `FINAL-REPORT.yaml` must be generated only after a deterministic evidence-closure validator proves all required raw artifacts and receipts exist and are internally consistent.

# 5. New anti-shortcut engineering controls — implement before rerunning the bake-off

The previous failure was possible because evaluator scripts were allowed to manufacture final-looking artifacts. Fix that first.

## C1 — raw-result-first contract

Every benchmark must follow:

```text
real invocation(s)
    -> raw per-case result(s)
    -> raw execution receipt(s)
    -> deterministic scorer
    -> comparison scorecard
    -> component decision
```

Never:

```text
evaluator source code
    -> preselected numbers
    -> scorecard
```

Required raw roots:

```text
artifacts/transcript_pipeline_v2/corrective-run/
  raw/
    cli-smoke/
    asr/
    map/
    support/
    reduce/
    product-baselines/
    p20-four-source/
    p21-fresh-e2e/
    p22-resume/
  receipts/
  scorecards/
  evidence-manifest.yaml
  corrective-selection.yaml
  corrective-final-report.yaml
```

Do not overwrite the failed attempt's evidence while rerunning. Keep the new run distinguishable.

## C2 — component identity receipts

Before a component can be scored, write a real identity receipt containing, as applicable:

- package import name;
- installed package version;
- model identifier/revision;
- model/runtime load success;
- executable path/version for CLI tools;
- actual smoke command;
- exit code;
- timestamp;
- hardware/runtime notes;
- no credentials.

A component without identity proof is `BLOCKED`, `NOT_INSTALLED`, or `UNMEASURED` — never silently simulated.

## C3 — semantic invocation receipts

Every real Map/Reduce semantic call used for benchmark evidence must record:

- provider ID;
- transport class;
- executable/version if observable;
- input packet SHA256;
- output SHA256;
- subprocess exit code;
- start/end/wall time;
- attempt count;
- TTK validator status/errors;
- output artifact path;
- sanitized environment policy result;
- no credential values.

## C4 — evidence references on every metric

Every metric row in every scorecard must contain either:

```yaml
evidence_refs:
  - path/to/raw/result.json
  - path/to/receipt.json
```

or:

```yaml
value: UNMEASURED
reason: ...
```

A score without evidence references must fail schema/validation.

## C5 — final evidence-closure validator

Implement a deterministic script such as:

`scripts/transcript_pipeline_v2/eval/verify_evidence_closure.py`

It must return non-zero if any required condition below is false:

1. selected semantic Map lane has real invocation receipts;
2. selected semantic Reduce lane has real invocation receipts;
3. all P20 sources have complete current Map coverage and valid Reduce/compile state;
4. P20 semantic receipts correspond to the P20 packet/output hashes;
5. P21 contains real fresh EN and DE ASR artifacts plus downstream semantic receipts;
6. P22 contains first-run and resume invocation ledgers proving idempotency;
7. no selected real component is backed only by a simulation adapter;
8. every selected-component metric has raw evidence references;
9. hard-gate states are derived from artifacts, not free-form booleans;
10. Trial-1 transport receipts contain no forbidden provider class;
11. required evidence files are hashed in `evidence-manifest.yaml`;
12. current Git commit/dirty-state provenance is recorded;
13. no mandatory stage remains `UNMEASURED`, `BLOCKED`, missing, stale, or pending;
14. `FINAL-REPORT` cannot say PASS if any hard gate is not PASS.

P16 selection and final report generation must call this validator.

## C6 — anti-synthetic-metric tests

Add tests that fail if benchmark scorecards are emitted without raw-case results.

At minimum test:

- deleting a raw result makes its scorecard invalid;
- changing a raw result changes recomputed aggregate metrics;
- a scorecard with a numeric metric but no `evidence_refs` fails;
- a P20 PASS without per-source invocation receipts fails;
- a P21 PASS without fresh ASR artifact hashes fails;
- a component named GLiNER2/mDeBERTa/HHEM/LangExtract without matching identity receipt fails;
