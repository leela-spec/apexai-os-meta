# Research and decision map

Existing work already covers instruction representation, loading, routing, skills, ownership, and enforcement. The next research should reconcile these into an evaluated activation-to-compliance design. The [seed note](apex-meta/informatics/final/research/11-infrastructure-evidence-index/sources/infrastructure-activation-research-brief.md) and [Handover 14, sections 2–3](apex-meta/informatics/final/research/11-infrastructure-evidence-index/remote-snapshots/HANDOVER-14-APEX-RULE-REGISTRY-AND-ACTIVATION-INTEGRATION.md#2-diagnosis--evidence-not-a-new-invented-architecture) frame that integration question. Neither proves that a unified runtime is installed.

## Empirical findings and attribution limits

- The [routing pilot, lines 24–49](apex-meta/informatics/final/operations/17-READ-TRACE-PILOT-AND-BASE-REF-FRAGILITY-FINDINGS.md) reports that handover and trade-off pointers were not opened in its small pilot. Its authors explicitly limit this to a go/no-go signal, not statistically confident per-gate rates. QMD retrieval: `#766215:15:35`.
- The [Round 2 verdict, lines 20–28 and 46–51](apex-meta/informatics/final/research/10-ultra-upgrade-validation/01-results-and-verdict.md) reports 18/33 baseline, 31/33 hooks plus reminders, and 17/33 deliberation on the tested Antigravity setup. T1 pre-read gains involved hook denials; T6/T7 gains involved concise reminders without Stop denials. QMD retrieval: `#ee34d4:12:40`. These are source-reported results, not reruns performed for this index.
- The same verdict records Arm C isolation limits, T3 over-application, model-specific reasoning behavior, and cross-harness limitations. The next study must retain these caveats and use the same cases for competing architectures.
- The [instruction-access matrix, lines 15–35](apex-meta/informatics/final/research/01-universal-instruction-research/05-INSTRUCTION-ACCESS-AND-SERIALIZATION-MATRIX.md) already separates representation from loading. Recasting XML as Markdown or a reference as a skill changes different mechanisms; test them separately. QMD retrieval: `#3b1382:15:35`.

## Live surfaces versus historical records

The [Claude project router, lines 3–30](.claude/CLAUDE.md) separates Weekly Orchestrator, explicitly activated Multi-Agent Orchestration, and the shared Plan-Sync-Session backbone. The [current manifest](apex-meta/orchestration/CURRENT-SYSTEM-MANIFEST.yaml) maps doctrine, runtime definitions, schemas, workflows, durable state, and deterministic computation. Preserve this separation in repository proposals.

The [local settings file](.claude/settings.json) contains `defaultMode` only at inspection time. That narrow observation does not establish the state of settings.local, global settings, other repositories, or the current Codex host. The [file catalog](apex-meta/informatics/final/research/11-infrastructure-evidence-index/02-file-catalog.md) covers existing skill entrypoints and agent definitions across vendor directories; file existence does not prove that the runtime discovers or activates them.

The predecessor KB [mechanism decision model](apex-meta/kb/claude-code-orchestration-design/wiki/summaries/claude-mechanism-decision-model.md) explicitly separates doctrine from implementation. Its [index](apex-meta/kb/claude-code-orchestration-design/wiki/index.md), source manifests, raw sources, and operator review log are already inventoried. Read these before commissioning another generic agent/skill/hook landscape review.

## Failure guards for the next prompt

Extract every current XML rule and meaningful downstream rule from live owners. Preserve original P0–P3 and raw I/E/R without inventing missing ratings. Keep proposed, accepted, superseded, and experimentally challenged positions distinct.

Validate activation and outcomes for chat-only answers, rankings, governed file creation, iterative research, compaction/resume, multi-rule engineering, and trivial negative controls. A hook-only plan that checks file writes cannot establish chat-answer compliance.

Resolve local/remote divergence and installed-version support before choosing infrastructure. The [retrieval and gap ledger](apex-meta/informatics/final/research/11-infrastructure-evidence-index/03-retrieval-and-gaps.md) records those boundaries. This index deliberately leaves the architecture choice open.
