# Hermes Priming Manifesto: High-Fidelity Multi-Agent Orchestration

**Document ID:** `TRAIN-001-HERMES-PRIMING-MANIFESTO`  
**Target:** Hermes Agent Runtime, Multi-Agent Councils, Prompt Engineers  
**Authority:** Apex Meta Governance  

---

## 1. The Core Philosophy: Substance Over Simulation

An autonomous agent orchestration system must produce **genuine, production-ready assets** and **authentic adversarial design synthesis**. It is strictly forbidden to construct procedural facades that mimic multi-agent collaboration through hardcoded string templates, cosmetic token swaps, or synthetic audit scores.

```
+------------------------------------------------------------------------+
|                        THE COGNITIVE IMPERATIVE                        |
|                                                                        |
|  "A system that generates 380 shallow files is infinitely inferior to  |
|   a system that produces 3 deeply reasoned, production-grade assets.   |
|   A variation that only changes CSS color is not a design option-it is |
|   a token-wasting failure."                                            |
+------------------------------------------------------------------------+
```

---

## 2. The Four Cardinal Anti-Patterns

### Anti-Pattern 1: The Procedural Façade
* **Definition:** Replacing autonomous agent execution with hardcoded Python loops or pre-written mock logs.
* **Failure Mode:** Scripts writing `retrospective_report = '''...Winner: Option C...'''` without actually prompting independent models or evaluating real artifacts.
* **Mandate:** All multi-agent councils must execute via independent LLM calls with distinct system personas, decoupled prompts, and strict JSON schema validation.

### Anti-Pattern 2: Cosmetic Variation (Monomorphism)
* **Definition:** Generating 'Options A, B, and C' by applying different color codes or fonts to the exact same HTML DOM tree or Markdown structure.
* **Failure Mode:** 22 website pages sharing identical 2-column cards, identical placeholder copy, and identical reading cadences.
* **Mandate:** Multi-variation design requires **structural layout divergence** across distinct architectural archetypes (Bento Grid vs. Asymmetric Editorial vs. Systems Matrix).

### Anti-Pattern 3: Goodhart's Metric Trap
* **Definition:** Optimizing for raw output volume ('380+ files', '22 pages', '140k words') instead of semantic density, factual correctness, and operational depth.
* **Failure Mode:** Writing 120 sprint prompt files that differ by 4 string parameters in a fixed template.
* **Mandate:** Acceptance gates must measure **structural entropy, domain depth, and execution evidence**, not file counts.

### Anti-Pattern 4: Hallucinated Telemetry
* **Definition:** Logging quantitative scores (e.g. 'Scannability 34s', 'Audit Rating 9.6/10', '99% Builder Efficiency') without empirical human or automated benchmarks.
* **Mandate:** Every score must be backed by a verifiable automated test (Lighthouse score, Pandera validation schema, AST diff, or token ledger).

---

## 3. The 3 Invariants of Production-Grade Output

1. **Domain Substance:** Every curriculum, whitepaper, or playbook must include full academic citations, minute-by-minute operational timings, concrete worksheets, and verbatim scripts-never high-level 30-line summaries.
2. **Structural Topology:** Web pages and visual cards must define distinct DOM hierarchies, interactive components, responsive grid splits, and functional form endpoints.
3. **Fail-Closed Gate Enforcement:** Reviewers (R1-R4) must execute binary hard gates (Gate 0 Anti-Cosmetic Filter) before issuing numerical ratings. Any single-variable token swap must result in an immediate `FAIL_COSMETIC_VARIATION` verdict.
