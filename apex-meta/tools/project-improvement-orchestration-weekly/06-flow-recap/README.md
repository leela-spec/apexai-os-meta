# Module 06 — Flow Recap

## Purpose

Turn actual execution evidence into a concise operator result and candidate downstream changes.

## Expected function

Answer:

- what actually happened;
- what was produced;
- what changed or was learned;
- what remains blocked/open;
- which project/task changes are candidates;
- what, if anything, requires review.

## Boundary

Recap may propose candidate changes but must not silently convert them into confirmed project truth.

## Module work

Compare the existing FlowRecap packet/agent with the recovered result-card design and the simplified evidence interface from Module 05. Remove duplicated planning/provenance boilerplate unless needed by a real consumer.

## Completion

Production integration -> Master verifies evidence lineage and downstream status-merge interface -> fresh W34-style evidence recap test -> operator acceptance.
