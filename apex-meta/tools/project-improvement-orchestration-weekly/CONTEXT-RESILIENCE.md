# Context and Token Resilience

## Goal

Make the improvement project recoverable after context compaction, a long Master session, or replacement by a fresh Master chat without requiring full-history replay.

## Principle: repository state over conversational memory

Conversation is working memory. This folder is project memory.

A fact that materially changes the improvement project's direction is not considered safely retained until it is reflected in `CURRENT-STATE.md`, `DECISIONS.md`, a module README/handover, or the actual production file it governs.

## Progressive loading

### Master startup minimum

Read only:

1. root `README.md`;
2. `CURRENT-STATE.md`;
3. `DECISIONS.md`;
4. `PROCESS.md` and `ORCHESTRATOR-DEFINITION.md` when role/process recovery is needed;
5. active module README;
6. production files explicitly referenced by the active module.

Do not preload all module folders, historic handovers, W34 artifacts, schemas and agent files.

### Worker/module startup minimum

A module chat receives a bounded handover generated by the Master. It should read:

- that module's README/handover;
- named production files;
- named upstream/downstream interfaces;
- relevant frozen test inputs.

It must not independently reconstruct the whole project unless it discovers a concrete contradiction and reports it to the Master.

## Current-state discipline

`CURRENT-STATE.md` must always answer:

- current phase;
- active module;
- last accepted result;
- current blocker/unresolved decision;
- exact next action;
- latest relevant commit/reference.

Keep it concise. It is a pointer map, not a narrative journal.

## Decision discipline

`DECISIONS.md` stores only durable decisions that future chats must obey or explicitly reopen. Each entry should include:

- decision;
- rationale;
- affected scope;
- status: locked / provisional / superseded;
- source/date;
- supersedes reference when relevant.

Do not copy whole conversations into it.

## Reference-over-copy rule

When upstream truth already exists, reference the repo path rather than reproducing it in project files. Duplicate only a concise invariant when a worker must see it immediately to avoid a known failure.

## Freshness rule

Every module handover must identify which paths are active authority and which are historical evidence. A fresh chat must never be asked to infer precedence from file dates or naming.

## Compaction recovery

If the Master loses context:

1. re-read root README;
2. re-read `CURRENT-STATE.md` and `DECISIONS.md`;
3. read active module README and its latest return/handover if present;
4. inspect actual production diff/state;
5. continue from the exact next action.

Do not rerun completed architecture research unless new evidence contradicts the stored decision.

## Bounded handovers

A handover should contain decisions and interfaces, not a full archive. It should answer:

- what this module is for;
- what is already decided;
- what is still open;
- which files to read/change;
- what upstream input it receives;
- what downstream consumer expects;
- what operator experience is intended;
- what constitutes implementation complete;
- how fresh testing will occur.

## Test-context isolation

Fresh test chats must not read this project folder unless the production runtime itself legitimately references it. The test is intended to prove the production skill/agent files are sufficient.
