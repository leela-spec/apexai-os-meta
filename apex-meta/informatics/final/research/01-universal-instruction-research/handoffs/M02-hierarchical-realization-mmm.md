## Research questions

1. Does hierarchical systems engineering/V-model remain the strongest established backbone?
2. Which machine-facing terms reduce ambiguity better than Macro/Meso/Micro?
3. Does the current direct/structured/recursive depth behavior match established practice?
4. Which traceability, verification, validation, and convergence rules are essential?
5. Which current rules duplicate M04 routing or M03 context management?
6. Can the current candidate snippet be shortened without losing useful behavior?

## Required outputs

1. Established-concept validation map.
2. Current MMM strengths/gaps.
3. 2–4 wording candidates, including retain-as-is.
4. Recommended short snippet or explicit `NO_CHANGE`.
5. Trigger/depth rule.
6. Focused-method changes only if justified.
7. Failure modes and examples.
8. Evaluation prompts.
9. Boundaries with M03/M04/M08.
10. Integration proposal preserving the existing MMM bundle as owner.

## Constraint

Do not create a second MMM definition, project-management framework, task state model, or orchestration topology.
