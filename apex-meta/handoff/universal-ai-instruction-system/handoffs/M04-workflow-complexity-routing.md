# M04 — Workflow & Complexity Routing

## Purpose

Standardize how an AI scales process depth to observable task properties.

## Operator intent

Simple work should stay direct. More structure should appear only when ambiguity, dependencies, architecture, context, or rework risk justify it.

## Research questions

1. Which established workflow patterns best support direct, chained, routed, parallel, orchestrated, evaluator-optimizer, and bounded recursive work?
2. Are the existing four Apex routes useful, excessive, or missing a meaningful case?
3. Which observable task properties should select a route?
4. When does parallel work outperform sequential work?
5. When should decomposition recurse?
6. Which recovery/stop rules prevent repeated repair loops?
7. How should routing activate M01 or M02 without duplicating them?

## Required outputs

1. Established-pattern map.
2. Comparison of 2–5 routing formulations, including retain-current.
3. Recommended 1–4 sentence snippet.
4. Observable trigger/depth rule.
5. Focused routing method.
6. Failure modes, especially ceremony and autonomous-agent overuse.
7. Simple/medium/complex/recursive examples.
8. Evaluation prompts.
9. Boundaries with M01/M02/M03/M05.
10. Integration proposal.

## Constraint

Do not create a numerical complexity score unless evaluation proves a clear benefit. Do not make multi-agent execution the default for large work.
