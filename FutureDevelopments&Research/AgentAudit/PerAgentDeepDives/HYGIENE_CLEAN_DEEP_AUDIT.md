## 9. Modern Architecture Alignment & WSL2 Integration Roadmap

### 9.1 Single-Engine WSL2 Storage Topology Alignment
Per `AGENTS.md`, ADR-002, and `05-program-closeout/PLAN.md`:
- **WSL2 Native ext4 Execution:** All Linux agent tools (`apex-sync`, `cross-linker`, python test harnesses) run strictly within native ext4 paths (`/root/workspaces/<repo>`), completely avoiding `/mnt/c` Windows 9P mounts. 9P filesystem latency causes severe I/O lag, false file-locking contention, and unkillable kernel D-state locks during multi-file lint sweeps.
- **Shared Engine Reality:** Single WSL2-native Docker daemon with shared PostgreSQL; Docker Desktop is retired.
- **File-Backed Persistence:** Hygiene Clean enforces the absolute invariant that lint sweep results and closure states are written directly to disk (`run-record.schema.md`, `handoff-packet.schema.md`). An interrupted run is 100% resumable from disk alone.

### 9.2 Plan-Sync-Session Backbone & Deterministic Sweeps Integration
Hygiene Clean check families integrate directly into the three-tier Python backbone:
1. **`apex-plan` (Planning Phase):** Hygiene Clean audits task definitions before acceptance, checking for broken prerequisites, unmapped paths, or missing project cards (Interface Check).
2. **`apex-sync` (Scoring & Validation Phase):** `scripts/apex_sync.py` executes deterministic dependency and pointer checks. If broken references or stale timestamps are discovered, `apex-sync` raises a P1/P0 finding, blocking dry-run confirmation until remediated.
3. **`apex-session` (Commit & Promotion Phase):** Prior to committing handoff packets to `apex-meta/handoff/`, Hygiene Clean verifies exact-preservation metrics and confirms that no undeclared files were modified in the commit.
