### 7.2 Preimage-Checked Scaffold Mutation Engine
The fundamental insight from `APPENDIX_KB_PREIMAGE_CHECKED_SCAFFOLD_MUTATION_PROCESS.md` is that:
1. **GitHub contents write is deterministic:** Submitting whole-file contents always stores exactly those bytes.
2. **AI replacement construction is probabilistic:** When an LLM regenerates a 1,000-line file, it silently compresses tables, deletes subtle docstrings, and omits edge cases.
3. **Commit diffs are deceptive:** Git will compute a localized diff even if the AI reconstructed the entire file, giving a false sense of safety.
4. **Mandatory APEX OS Defense:** Every automated editing tool MUST verify the exact live preimage anchor before submitting changes.

### 7.3 Hard Routing Signals State Machine
Prompts & Workflows replaces conversational text warnings with hard, deterministic execution signals:
- **`GATE_CHECK`:** Pre-execution verification of task ID, scope lock, target path, and authority.
- **`HALT`:** Mandatory abort when preimage anchors are missing, duplicate, or stale.
- **`CLARIFY`:** Mandatory hold when operator intent conflicts with existing file structure.
- **`SPLIT_REQUIRED`:** Mandatory task decomposition when output token budget is exceeded.
- **`TASK_CLOSURE`:** Cryptographic or line-verified proof of task completion committed to disk.

## 9. Modern Architecture Alignment & WSL2 Integration Roadmap

### 9.1 Single-Engine WSL2 Storage Topology
In full compliance with ADR-002 and `AGENTS.md`:
- **Filesystem Isolation:** All Linux agents run exclusively inside native ext4 workspaces (`/root/workspaces/<repo>`), completely avoiding `/mnt/c` Windows 9P mounts. 9P filesystem latency creates unkillable kernel D-state locks, CPU thrashing, and corrupted git index writes.
- **Elimination of MAX_PATH Constraints:** Running inside native Linux ext4 completely eliminates the 260-character Windows path limit observed in legacy deep research folders (`Recap&ProcessImprovs`), ensuring safe traversals across deep skill and test hierarchies.
- **Deterministic File Locking:** Native ext4 filesystem semantics guarantee atomic file locking during multi-agent concurrent reads and writes.

### 9.2 Plan-Sync-Session Backbone Integration
Prompts & Workflows provides the execution harness templates for the three-tier Python backbone:
1. `apex-plan` decomposes user stories into atomic task payloads adhering to `03_TASK_PAYLOAD.md` with explicit input refs and non-goals.
2. `apex-sync` (`scripts/apex_sync.py`) verifies preimage anchors, validates dependency readiness, and previews registry changes before write submission.
3. `apex-session` formats and verifies H6 handoff packets (`handoff-packet.schema.md`), records durable closure proofs (`08_TASK_CLOSURE.md`), and updates the persistent task board.
