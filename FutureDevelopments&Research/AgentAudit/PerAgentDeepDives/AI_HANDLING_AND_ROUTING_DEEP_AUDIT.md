### 7.2 The 500-Token Primacy Rule & Positional Attention Decay
Modern transformer models allocate maximum attention to the first 500 tokens of the input stream. When critical instructions (e.g. halt triggers, output constraints, forbidden actions) are buried at token position 1,500 or beyond, empirical adherence drops from **73% to 30%–50%**. Staging and enforcing the Critical Directives block (CD-01..CD-05) ensures all APEX OS subagents operate with maximum constraint fidelity.

### 7.3 Model Directive Ceilings & Cognitive Saturation Physics
Large language models experience cognitive saturation when overloaded with imperative rules. Crucially, the decay curves differ by model architecture:
- **GPT-4o:** Follows an exponential decay curve. Above 50 directives, compliance collapses across all categories.
- **Claude 3.7 Sonnet Standard:** Exhibits linear decay. Prioritization tags (`# tier: critical`) are required to prevent low-stakes formatting rules from displacing architectural boundaries.
- **Claude 3.7 Sonnet Reasoning:** Thinking tokens buffer cognitive load, raising the ceiling to 80 directives.
- **Gemini 2.5 Pro & OpenAI o3:** Feature threshold decay with high stability up to 100 directives, followed by a sharp cliff between 150–250 rules.

### 7.4 Context Window Budget Allocation, Decay & Re-injection
As sessions extend and cumulative tokens exceed 80,000 tokens, attention distribution flattens, increasing the risk of subtle instruction drift. Under the rescued doctrine, when an active run detects context drift past 80k tokens, it must re-inject the critical directive block as a prefix reminder. If drift persists, execution immediately halts with an `E1` state snapshot, forcing a clean session restart.

### 7.5 Local vs. Cloud Routing Policies, Cost Classes & Scarcity Invariants
APEX OS adopts a strict resource preservation hierarchy:
1. `local_zero_cost`: WSL2-native Ollama models running on NVMe ext4 storage are the default choice for routine repository indexing, syntax checks, and file classification.
2. `metered_economy`: Low-cost batch APIs (Gemini Flash, Haiku) handle high-volume summarization.
3. `metered_standard`: Standard production models (GPT-4o, Sonnet standard) execute deterministic multi-file edits.
4. `subscription_frontier` / `metered_frontier`: Frontier reasoning models (o3, Sonnet 3.7 Thinking) are strictly reserved for complex architecture design, security reviews, and resolving double-failure escalations.

## 9. Modern Architecture Alignment & WSL2 Integration Roadmap

### 9.1 Single-Engine WSL2 Storage Topology & Engine Boundaries
Per `AGENTS.md`, ADR-002, and `05-program-closeout/PLAN.md`:
- **Filesystem Isolation:** All Linux agents run exclusively inside native ext4 workspaces (`/root/workspaces/<repo>`), completely avoiding `/mnt/c` Windows 9P mounts. 9P filesystem latency creates unkillable kernel D-state locks, CPU thrashing, and corrupted git index writes.
- **Single Shared PostgreSQL Engine:** Docker Desktop is permanently retired. All database operations and local routing ledgers reside on native ext4 Docker volumes.
- **Durable File-Backed State:** Ephemeral chat memory is never trusted. All routing decision cards, budget plans, and usage deltas are committed to disk before turn boundaries.
